## 两道真实增强问答

1. 原问题：“文件导出取消了，临时文件和任务要咋处理？”
   - 改写为：“文件导出取消后，临时文件和导出任务如何处理？”
   - 两种问题分别执行 dense 与 BM25，每路最多 5 个原文片段，合并做一次 RRF。
   - 原问题与候选原文交给百炼重排，之后扩展父片段。
   - 生成回答包含取消/成功后的临时副本清理、保留用户已保存文件、会话退出不延续导出等，并可回查原文。
   - 端到端约 11.852 秒（本次样例，非性能基准）。
2. 原问题：“调试页相机状态卡片离开页面时怎么处理？”
   - 改写模型返回原问题，因此保留两路召回。
   - 重排、父片段扩展与生成通过；回答涉及解除订阅、重新进入读取最新快照、避免重复观察者，以及卡片与悬浮层的独立生命周期。
   - 端到端约 3.241 秒（本次样例，非性能基准）。

对照模拟原文检查，示例回答的主要步骤能在相应段落找到依据；结构校验不等于自动证明每一句语义正确。更大题集、无答案题、多轮题和业务资料评测仍待开展。

## 当前运行与复现

本机服务入口：[http://127.0.0.1:8001/](http://127.0.0.1:8001/)。本次按用户授权开启 `.env` 的外部调用、Query 改写和 Reranker 三个开关。页面的本地检索与本地证据预览仍不计模型费用；生成时勾选增强复选框才会同时尝试改写与重排，普通生成只调用生成阶段。

真实增强验收脚本为 `scripts/verify_p2_remote.py`，执行前必须显式添加 `--allow-paid`，限于本机、已发布的模拟库与固定两题。不要为了查看报告重复执行收费验证。

```powershell
uv run --no-sync python scripts/verify_p2_remote.py --allow-paid
```

实际运行证据保存在本机忽略 Git 的文件中：

- `runtime/P2-local-verification.json`：四题本地验收，生成时外部调用关闭，付费次数为零。
- `runtime/P2-live-api-verification.json`：两题真实 API 响应、检索轨迹、引用与费用前后对比。
- `runtime/P2-browser-verification.png`：页面证据预览截图。
- `runtime/server-process.json`：当前本项目后台进程和日志位置。
