## 实际运行链路

```text
8 份模拟 Markdown/TXT
→ SQLite 保存独立库的原文修订和父子片段
→ 34 个子片段窗口远程 BGE-M3 编码
→ 本机 Milvus 写入 dense 和 sparse
→ 校验维度、数量、向量内容、原文映射及双路试检索
→ 发布新的 generation
→ 原问题远程编码
→ dense Top5 + sparse Top5
→ 去重与一次全局 RRF
→ 父片段扩展和上下文组装
```

验证问题为“文件导出取消后需要清理什么？”，上下文命中预期的 `demo-file-export`，并包含模拟验证及生命周期资料。问题和答案依据均属于模拟规范，不能据此回答公司业务；公司资料的 ZIP 保留规则与该模拟场景不同。

本轮未启用 Query 改写、百炼 reranker 或 DeepSeek 生成。因此本记录证明的是远程编码、双路召回与上下文链路，不能宣称“改写后的四路召回＋真实重排＋引用生成”已完成联合验收，也不构成召回率或回答准确率评测。

本次两路 Top5 候选集合相同、排序不同；这证明双路和融合能够运行，尚未证明 sparse 增加了正确证据或提高了检索效果。效果差异需要固定评测集对照。
