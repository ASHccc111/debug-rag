# BGE-M3 远程接口要求

确认日期：2026-11-01。用户决定 BGE-M3 不在自己的笔记本运行，采用服务器部署或 API。当前没有远程服务，先整理接口要求；本轮不订购服务、不下载 BGE-M3、不进行付费调用。

公开供应商、价格、输出能力与采购前核实项见 [远程服务采购调研](BGE-M3远程服务采购调研.md)。供应商候选不代表远程适配和真实验证已经完成。

## 1. 哪些地方会变化

未来由远程服务接收文本、运行 BGE-M3、返回 dense 和 learned sparse。Python RAG 编排、原文管理和 Milvus 可以继续留在本机。

```mermaid
flowchart LR
    D[文档子片段 / 用户问题] --> A[本机远程编码适配器]
    A --> R[服务器或 API：BGE-M3]
    R --> V[dense 与 learned sparse]
    V --> M[Milvus 两种向量的存储 / 检索]
    M --> F[RRF 与去重]
    F --> K[单独的 Reranker]
    K --> C[原文证据选择与生成]
```

这是目标链路，不是已经接通的接口。当前已构建的 light 索引仍是本地 bge-small 512 维基线，不会仅因修改规划就自动变成 BGE-M3。

## 2. 准备服务器或 API 时需要提供什么

| 信息 | 具体要求 |
|---|---|
| 服务身份 | 服务商与文档链接，或自有服务器部署说明 |
| 访问地址 | 实际请求 URL、网络能否从运行 RAG 的机器访问 |
| 认证方式 | 使用用户自己的凭据，通过本机环境配置保存，不在聊天或仓库中提供密钥 |
| 模型 | 明确为 BAAI/bge-m3；若实际使用其他模型，要按真实型号另建索引并命名 |
| 模型版本 | 权重 revision、文件摘要或足以固定服务行为的版本标识，不能只给会漂移的服务别名 |
| 输出能力 | 同一输入能取到 dense 和 learned sparse，不能只有普通 embeddings 数组 |
| 批处理 | 最大 batch、最大输入 token 数、超长处理规则、批次返回顺序或 index |
| 运行约定 | pooling、归一化、精度、tokenizer/词表、文本截断规则和查询/文档处理规则 |
| 可靠性 | 超时、限流、错误码、请求标识，失败不能返回看起来成功的空向量 |
| 费用 | 按 token、按调用或服务器时间计费；收费规则需能核对并纳入约定预算 |

如果是现成 API，先要一份实际响应样例确认 sparse 能力，再决定是否使用。仅声明“支持 BGE-M3”不代表它暴露了全部模型输出。

## 3. 建议的返回契约

下面是拟接入适配器需要的信息，不是假定所有服务商都有同名字段。实际 API 的字段可以由适配器转换。

| 字段 | 期望类型与作用 |
|---|---|
| model | 实际模型名称 |
| model_revision | 可固定的模型/服务版本 |
| data[i].index | 对应请求 texts 中的原始位置，避免向量和原文错配 |
| data[i].dense | 浮点数数组；BGE-M3 标准 dense 为 1024 维 |
| data[i].sparse | token_id 到权重的映射，或等价 indices/values 数组 |
| usage | 若是收费 API，提供计费使用量；缺失时需有可执行的保守预留规则 |
| request_id | 可用于核对接口错误与用量的请求标识 |

sparse 的词项 ID 必须属于一致的 tokenizer 词表，不能把“本句第几个词”当成全局词项维度。文档与问题需要使用同一套词表和编码配置。

若自建服务，可以封装一个 encode 路由，请求中指定 texts 及需要 dense/sparse。它是我们制定的服务契约；填写一个 config 字段不会让已有的纯 dense 服务自动输出 sparse。

官方模型使用示例中通过 `return_dense=True`、`return_sparse=True` 获取这两种表示，输出中包含 `dense_vecs` 与 `lexical_weights`。参见 [BGE-M3 官方模型说明](https://huggingface.co/BAAI/bge-m3) 与 [FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding)。Reranker 是另一个组件，不由下载或调用 BGE-M3 自动获得。

## 4. 接通前先用模拟资料验证

1. 两三条短文本请求，确认返回数量、index、向量维度与数值有效性。
2. 同一文本重复编码，检查配置稳定性，记录精度允许的误差。
3. 同一词项在不同输入中的 sparse ID 属于同一词表。
4. 文档/查询的两种向量都能写入并检索 Milvus，保留原文 ID 映射。
5. 新建独立 BGE-M3 索引 generation；不混进已有 bge-small 向量空间。
6. 保留 dense、sparse、融合、重排的独立轨迹，再用固定测试集比较效果。

远程 Embedding 会接收文档正文和问题，所以必须执行相应的资料外发许可检查；许可不只针对最终生成模型。
