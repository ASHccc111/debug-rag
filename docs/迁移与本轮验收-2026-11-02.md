## 本轮实现

工程路径：页面提交本地构建 → SQLite 保存任务 → 每库任务锁/构建锁 → 构建阶段回调 → 校验 → 事务发布 → 页面轮询结果。失败保留旧代；重启只恢复已无存活锁持有者的任务。若发布已成功但任务确认丢失，恢复时对账补记成功。文档新增/替换/移除仍先通过 CLI 全量准备，再构建；页面不会自动扫描原目录。

远程路径：完整原始问题 / 可选单条改写 → 每个问题一次远程双表示编码 → dense / learned sparse 各路 TopK → 按原文 chunk 单路去重 → 一次全局 RRF → 独立 Reranker → 同代父片段扩展 → 引用答案。

TopK 分别由 `RAG_DENSE_TOP_K`、`RAG_SPARSE_TOP_K`、`RAG_BM25_TOP_K` 配置，当前每路 1–5，最多四路 20 个候选，与现有重排上限一致。`RAG_RRF_K` 默认 60。改写相同或失败时保留两路。light 继续 dense＋BM25，hybrid 使用 dense＋learned sparse，两者分开记录。

火山词项作为不透明字符串处理；每代索引保存排序后的无碰撞整数词表，查询只保留本代已知词项。模型、endpoint、服务配置 revision、窗口和向量维度属于 pipeline 身份；不匹配就拒绝检索。`default` 不能保证上游权重固定，服务变更需更新配置修订并重建。
