DOC-01-B000004 已有功能入口
DOC-01-B000005 DebugActivity 提供热区、测试网络环境、悬浮窗及字段选择等快捷设置，状态概览可点击复制。相机数据和日志导出跳转到各自 Activity；连接诊断、固件通信入口当前统一提示开发中。

DOC-01-B000007 实时数据的两条路径

DOC-01-B000010 展示配置的实际边界
DOC-01-B000011 通用配置枚举定义主面板最多 12 个字段、悬浮窗最多 8 个字段、详情页不设数量上限。当前主要接通悬浮窗字段选择；不能把枚举的存在解释成所有页面已经完成统一配置。
DOC-01-B000012 DebugDisplayConfigStore 当前为进程内存存储。null 配置意味着使用默认值，空选择意味着用户主动不显示字段；重启后的持久化不是现有实现承诺。
DOC-01-B000013 导出和构建边界
DOC-01-B000014 当前导出五类选项是应用构建、账号设备、手机性能、相机数据与 App 日志。App 日志选择可读文件中最后修改的一份；快照数据取导出时可读的最新状态。
DOC-01-B000015 Gradle 已配置 withDebug 与 withoutDebug 及变体过滤。Release 的实际依赖和 APK 内容、Jenkins 产物仍需检查，配置文件不能替代产物级验证。
DOC-01-B000016 交付状态判断
DOC-01-B000017 现有能力清单用于说明源码范围，验收应针对具体构建、设备与固件版本执行。多设备、运行码率、相机日志、历史 CSV、折叠吸边及跨 App 使用需要分别确认实现与验证状态。

### DOC-02 docx/02_Debug 入口 SPI 与初始化契约.docx
DOC-02-B000001 Debug 入口 SPI 与初始化契约
DOC-02-B000002 Debug 对宿主提供 DebugFeature 门面，通过 RemoServiceLoader 查找 IDebugService；实现模块使用 AutoService 注册。当前分支的依赖注入改造尚有签名与类型归属问题，接入前必须核对。
DOC-02-B000003 适用分支 p/caijiamin/feat_debug_2th
基线提交 9010928ca51c6e766f75414c49c748338e0b7ecb
资料日期 2026 年 11 月 3 日
DOC-02-B000004 入口如何被装配
DOC-02-B000005 withDebug 源集中的 DebugTailApplication 继承 TailApplication，在 onCreate 中调用 DebugFeature.initialize(this)。DebugEntryActivity 调用 DebugFeature.open 后结束自身，具体页面在 debug_impl 内。
DOC-02-B000006 DebugFeature.service 使用 loadNotNull 获取 IDebugService；因此依赖声明、SPI 生成注册和实现打包是同一条接入链路。只有 API、没有实现或注册产物时，不能假设门面会自动静默忽略调用。
DOC-02-B000007 页面打开的 Context 规则
DOC-02-B000008 DebugFeature.open 请求 service 创建 Intent；当 Context 不是 Activity 时加入 FLAG_ACTIVITY_NEW_TASK。DebugSDK.open 也存在类似页面打开路径，但应注意它与 SPI 门面的初始化路径并非完全相同。
DOC-02-B000009 Manifest 中 Debug 主页面、相机详情和导出页面均设置 exported=false。接入说明应记录实际 Activity 名称，包括现有 ui.cmera 包路径，不能自行改成更常见的 camera 拼写。
DOC-02-B000010 当前静态不一致
DOC-02-B000011 IDebugService 声明 initialize(application) 和 initialize(application, dependencies) 两个方法；DebugServiceImpl 只实现单参数版本。该实现内调用 DebugRuntime.initialize(application)，而 Runtime 定义的是要求 dependencies 的双参数版本。
DOC-02-B000012 API 侧的 IDebugService 与 DebugFeature 引用了 DebugDependencies，但该类型位于 debug_impl。debug_api 的构建依赖未声明 Impl，且架构上也不应倒依赖 Impl。这些是静态检查发现的契约问题，本轮没有执行编译来产生构建结论。
DOC-02-B000013 后续对齐的验收要求
DOC-02-B000014 修复时应同时确认公开依赖类型所在模块、服务方法实现完整性、门面到 Runtime 的参数传递，以及默认依赖语义。不能仅在文档里给出一个能够绕过 SPI 的调用片段，然后宣称原接入路径正常。
DOC-02-B000015 验证顺序建议先检查 debug_api 的类型可见性，再检查 debug_impl 和 KSP 注册，最后构建 App 的允许变体。文档在问题解决前保留此限制，不提供标为可直接运行的宿主 Adapter 教程。

### DOC-03 docx/03_Debug 运行时装配与资源生命周期.docx
DOC-03-B000001 Debug 运行时装配与资源生命周期
DOC-03-B000002 DebugRuntime 持有采集器、相机监听、悬浮窗控制器及通用数据组件，是进程级装配中心。页面仅订阅展示所需状态，不应重复创建全局采集器。
DOC-03-B000003 适用分支 p/caijiamin/feat_debug_2th
基线提交 9010928ca51c6e766f75414c49c748338e0b7ecb

DOC-03-B000004 组件创建顺序
DOC-03-B000005 初始化先创建 DebugDataRegistry、DebugStateStore、DebugDisplayConfigStore 和 DebugDataReceiverImpl，然后由 PhonePerformanceSource 注册内置设备与字段。热区控制器、性能采集器、相机监听和悬浮窗控制器分别注册生命周期或事件。
DOC-03-B000006 性能监听连接到 PhonePerformanceSource.update，Runtime 保存相同监听实例用于解除订阅。组件保存后才启动可选的宿主 dataProvider；Provider.start 接收共享 receiver。
DOC-03-B000007 主线程和幂等性
DOC-03-B000008 DebugSDK.initialize、open、release 检查主线程；SDK 和 Runtime 各自保存初始化标记。重复 initialize 在各自标记已设置时返回，不能用重复初始化替代变更 Provider 的正式接口。
DOC-03-B000009 startDataProvider 会比较实例、停止旧提供者再启动新实例，但目前是 Runtime 的私有初始化路径。它不等于宿主已经拥有一个公开的热切换 Provider API。
DOC-03-B000010 页面订阅范围
DOC-03-B000011 主页面在 onStart 加入性能、相机、热区、悬浮窗开关和字段选择监听，在 onStop 移除，并关闭弹窗。相机详情也按页面可见生命周期订阅，不负责全局事件注册。
DOC-03-B000012 新监听者是否立即收到最近值由对应组件决定：性能和相机监听会回放最新快照；Registry 的监听注册不立即回放，订阅者需要读取当前注册信息。
DOC-03-B000013 释放顺序
DOC-03-B000014 Runtime.release 先停止 activeDataProvider，再释放悬浮窗，移除性能转发监听并释放采集器，注销相机事件，释放热区，最后丢弃注册、状态和配置组件引用。SDK.release 还会复位自己的标记。
DOC-03-B000015 悬浮窗 release 清理 Handler、生命周期监听、弱引用和操作回调。相机 unregister 移除 EventBus 订阅、设备名请求集合和延迟回调；不要把注销理解成所有快照对象一定已经被手工置空。
DOC-03-B000016 异常和重入检查
DOC-03-B000017 当前初始化过程不是一个完整的失败回滚事务。若 Provider.start 或中途注册抛错，需检查是否存在部分注册资源与初始化标记不一致；这属于建议验证场景。
DOC-03-B000018 接入测试要覆盖重复初始化、重复释放、释放后重新初始化、页面切换以及 Provider.start/stop 失败。对照监听次数和事件输出，不能只以页面能打开判定没有泄漏。

### DOC-05 docx/05_手机性能采样机制与指标解释.docx
DOC-05-B000001 手机性能采样机制与指标解释
DOC-05-B000002 AppPerformanceMonitor 采集当前 App 进程的性能近似状态，约每秒生成一份快照。CPU、PSS、堆内存与 FPS 使用不同测量口径，不能互相代替。
DOC-05-B000003 适用分支 p/caijiamin/feat_debug_2th
基线提交 9010928ca51c6e766f75414c49c748338e0b7ecb
资料日期 2026 年 11 月 3 日
DOC-05-B000004 采样何时启动
DOC-05-B000005 采集器监听 Application.ActivityLifecycleCallbacks，以 startedActivityCount 记录 started 的 Activity 数。计数由零变一时启动；全部停止后取消采样与 Choreographer 帧回调。
DOC-05-B000006 采样通过主线程 Handler 以 1000 毫秒延迟循环。实际间隔可能因主线程调度变长，计算使用相邻采样的 elapsedRealtime 差值，而不是直接假设恰好一秒。
DOC-05-B000007 CPU 使用率
DOC-05-B000008 分子是 Process.getElapsedCpuTime 的增量，分母是经过时间再乘可用 CPU 核数，最终乘 100 并限制在 0 到 100。该值是按核心数归一化的进程 CPU 指标。
DOC-05-B000009 它不是整机总 CPU 占用，也不能与没有除核心数的监控工具直接比较。排查时同时记录设备核心数、采样时长和构建类型，避免把口径差异当作采样错误。
DOC-05-B000010 内存口径
DOC-05-B000011 PSS 从 ActivityManager.getProcessMemoryInfo 获取当前 PID 的 totalPss，除以 1024 显示为 MB。Java Heap 为 Runtime.totalMemory 减 freeMemory，再除以 1024 的平方；Native Heap 使用 Debug.getNativeHeapAllocatedSize。
DOC-05-B000012 这些字段不满足简单相加等于 PSS 的关系。PSS 读取失败时当前实现以零参与构造快照，这与明确的空值状态不同；解读为零内存使用之前应核实采集是否成功。
DOC-05-B000013 帧率和温度
DOC-05-B000014 FPS 是采样期间 Choreographer 回调次数乘 1000 再除以实际毫秒数。它表示应用帧回调频率，不是相机传感器帧率、编码器输出帧率或直播接收端帧率。
DOC-05-B000015 电池温度通过 ACTION_BATTERY_CHANGED 最近广播读取 EXTRA_TEMPERATURE，除以 10 得到摄氏度。无广播或缺失温度返回 null；不能将它称作 CPU 温度。
DOC-05-B000016 采集和历史数据边界
DOC-05-B000017 latestSnapshot 只保存最近一次结果，监听者注册后可立即收到它。该类没有长时间采样持久化、CSV 累积或历史区间查询。二期性能导出需要另建带时间戳的记录能力。
DOC-05-B000018 release 在主线程解除生命周期注册，停止采样、清空监听和最新值。验证应覆盖前后台、多个 Activity 重叠 started、屏幕旋转及释放后无回调。

DOC-13-B000014 clearDevice 删除设备所有来源值；clearDeviceSource 删除一台设备一个来源；clearSource 删除所有设备的同一来源；clear 删除全部实时缓存。
DOC-13-B000015 Receiver 调用清理时还会维护 Registry，单独调用 StateStore 不会自动删除设备定义。业务应通过正确所有者执行组合操作。
DOC-13-B000016 新鲜度与历史能力
DOC-13-B000017 StateStore 的值没有通用时间戳、TTL 或 stale 状态，因此“有值”不等于“刚更新”。相机旧链路的 receivedAtMillis 不能自动提供给所有通用字段。
