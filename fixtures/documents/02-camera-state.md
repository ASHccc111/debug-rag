# 相机状态展示接入

本文是模拟接入规范，适用于 DemoDebug demo-v1；其中组件名是教学约定，与真实公司工程无关。

## 前置条件

先在演示环境启用相机模拟器，并确认当前会话已经初始化。状态只读取模拟器提供的快照，不访问真实相机或读取用户照片。调用方必须先明确展示在调试页卡片还是应用内悬浮层。

## 数据字段与含义

| 字段 | 示例 | 解释 |
| --- | --- | --- |
| camera_id | demo-front | 模拟设备标识 |
| phase | previewing | 当前模拟阶段 |
| permission | granted | 模拟权限状态 |
| observed_at | 演示时间 | 最近一次收到快照的时间 |

phase 的可用值为 closed、opening、previewing、error。没有新快照时显示“暂无状态”，不可把旧的 previewing 当作当前状态。permission 与 phase 分别展示，权限已允许不代表正在预览。

## 接入步骤

1. 在会话初始化之后注册状态观察者。
2. 把模拟器快照转换为展示模型，保留 observed_at。
3. 根据选定位置连接调试页卡片或应用内悬浮层。
4. 进入前台时读取一次当前快照，并订阅后续变化。
5. 离开对应展示生命周期时解除订阅，具体退出条件见生命周期说明。

开始绑定之前，调用方应明确自己持有的是页面生命周期还是应用前台展示生命周期。卡片跟随调试页进出，应用内悬浮层跟随前台展示宿主；不要因为它们展示相同字段，就把两个消费者的退出条件合并。会话状态源可以复用，展示订阅需要分别登记，便于检查是否遗留。

展示模型应保留状态源给出的观测时间，同时区分“尚未收到快照”和“收到 closed 快照”。这两个情况都可能没有预览画面，但含义不同。前者应显示暂无状态，后者应明确显示已关闭。收到 error 时展示脱敏说明，不能把上一次 previewing 继续当作正常状态展示。

绑定动作应当可以重复调用而不累计观察者。进入展示生命周期时先检查是否已经绑定；已绑定则更新当前展示，不再增加订阅。解除动作也应允许重复执行，在未绑定时安全结束。这里描述的是模拟行为要求，并不指定真实 Android 工程中的接口、线程框架或类名。

两个位置同时开启时，可通过同一组模拟状态变化观察数据一致性：两者应显示相同的 phase 和 observed_at。随后关闭悬浮层，确认卡片仍能更新；再打开悬浮层并退出调试页，确认悬浮层继续更新。这个顺序能分别检查共享状态源和独立退出条件，不能仅凭一次截图判断整个接入流程正确。

完成一次接入后，应把展示位置、前置模拟条件、观察者绑定点、退出清理点和实际执行的验证步骤写入演示记录。对没有执行的异常分支明确标记待验证。若没有可用的真实接口资料，回答应停留在这些流程约定，不能补造工程文件路径、注册 API 或公司内部模块名称。

## 异常展示

状态源报错时保留错误阶段和脱敏错误说明，不输出设备序列号或账户信息。缺少快照时不能伪造正常状态。定位问题先看 observed_at 是否变化，再检查观察者是否仍然注册。
