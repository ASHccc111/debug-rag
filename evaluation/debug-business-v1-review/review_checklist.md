# 人工审核清单

当前 60 题统一 pending；本文件没有审批签名。本轮 Agent 与程序没有权限替代人工批准。先核对语料和逐题语义，再决定是否建立正式冻结版本。

## 审核准备

1. 保存当前输出与原始 30 份资料；核对 corpus_manifest 的真实 SHA-256、版本声明与 corpus_digest。
2. 确认业务适用分支/提交和资料日期。源码未提供时保留 not_available；以后拿到对应源码可另记只读交叉核对范围，不把代码事实暗中添加为文档答案。
3. 查看 validation_report、validator_self_test、extraction_audit 与 review_queue，区分程序检查、Agent 提取核对和人工审核。
4. 审核人需访问 test 时按团队授权处理。生成 Agent 读过 test，因此本次不是严格盲测。后续模型与检索调参使用 dev。

## 每题必须检查

- [ ] 问题独立、清楚，1–300 个 Unicode 字符，不依赖聊天历史，不暗示答案或直接给出证据位置。
- [ ] 用户目标真实对应文档任务；没有用目录、作者、标题或同义改写凑数，也不声称来自真实用户日志。
- [ ] 主类别符合 boundary > status > cross_document > operation > fact 的优先级；专题按主要目标计数。
- [ ] 在原 DOCX/PDF 原生位置回查：DOCX body_index 包含表格，表格行/格/段落从 1 计数；PDF 用物理页和真实左上角 bbox。
- [ ] 逐字摘录连续且完整，字符区间按 Python 切片；没有跨块拼接、省略号改写或错用来源版本。
- [ ] 放大 PDF 原页逐题核对下划线、大小写、长标识符、类型、单位、表达式、表格行列和换行。保留断行不等于原 ID 含换行；如要修复需新建 before/after/理由/核对方法记录。
- [ ] 图示节点与箭头关系已读懂，或有明确正文支持；图示布局不证明代码执行顺序，更不证明已验收。
- [ ] 每个 required_point 是可单独判断的事实/必要步骤，证据足够；没有把多个无关任务揉成一个要点。
- [ ] 每个 support_set 的 AND 关系确有必要，OR 替代关系正确。充分的其他文档/段落是否应该补为替代来源，避免漏标导致检索被误判。
- [ ] 全部正向引文都参与必要要点，没有无关引用凑 PDF 或文档覆盖。
- [ ] reference_answer 覆盖全部要点，没有文档外补充。literal 是确需准确保留的标识符，而非以背 API 符号代替业务判断。
- [ ] critical 的设置与遗漏影响相符；forbidden_claims 是具体错误或不可凭资料断言的结论，直接反证编号准确。没有资料支持不等于现实中必然为假。
- [ ] 没混淆“未提及”与“未实现”、“有代码/类型/配置”与“编译/设备/CI 通过”、“现状”与“二期目标”。验证方法不是执行记录。
- [ ] operation 的必要条件和先后依赖来自原文；无依赖的步骤不强求唯一顺序，症状不被唯一归因到未证实原因。
- [ ] cross_document 去掉任何被声称必需的文档后是否仍能完整回答？若能，补充真实跨文档目标或重新分类，不凭两个引用数量认定通过。
- [ ] status 的时间/版本范围明确，适当保留静态检查、部分实现、规划和待验证边界。
- [ ] insufficient_evidence 的具体缺失事实确已全文核对，scope 不是正向 gold；没有因检索没命中就断言业务不存在。
- [ ] out_of_scope 目标明确超出 Debug 职责，而非业务范围内资料不足；没有伪造证明外部任务超范围的引文。
- [ ] clarify 仅缺一个必要条件，两个有来源的解释确实导致不同操作/回答；若能直接回答共同事实或自然给出完整答案，不应强制追问。
- [ ] boundary 的 required_points 为空、retrieval_scored=false，响应要求只围绕用户目标，不增加无关负担。
- [ ] 比较同类及跨 split 题目，是否有意图、决定性答案和条件相同的同义题或无影响实体替换。共享原文可以，不应把同族拆进两边。

## 记录与处理

逐题另建真实人工审核记录，建议列：case_id、审核人、含时区的实际时间、批准/需修订/退回、依据位置、问题说明、修订建议、复核人。不要在本轮草稿中预填人名或日期。

批准时由真实审核人将 review.human_status 填为 approved，并填写真实 approved_by、含时区 approved_at；退回时使用 rejected 并保留原因与同样真实审批字段。pending 保持两项为 null。需修订的题先保留 pending、在 notes 和审核记录说明，或明确退回；不能改完后自动批准。

本次 validate_dataset.py 是草稿模式，会拒绝 approved/rejected，这是预期行为。人工批准后的发布校验和冻结标识需要后续正式流程，不能用这次草稿校验代替批准。

若发现确定的语义冲突、缺证或无法消解歧义：列入 review_queue，给出两个版本/位置与影响题目；从可评分候选排除，重新报告实际配额缺口并标 incomplete。不要为了凑 60 题保留已知不合法项。仅正常待审核并不代表题目已知有错。

## 整体验收

- [ ] 逐条处理六份 PDF 的提取边界；所有纳入题目的原页细节复核完成。
- [ ] 问题族语义去重完成，改题后重新按固定算法分配并确认配额；不因某个 RAG 对 test 的表现而调整题目。
- [ ] 保留 30 份语料身份；50 道 answered、29 份当前正向来源和 6 份 PDF 的必要性逐项确认，新增或排除后重新计数。
- [ ] 原始召回/融合/rerank/父片段扩展的评测阶段、K 和运行时跨度匹配规则在后续执行器中另行实现验证。
- [ ] 不将评测题目、参考答案和标注入库，不基于 test 调参。
- [ ] 经真实审核批准后建立批准记录与冻结标识。修改语料、题目或标注需新版本、保留旧版和理由，所有对比方案在同一版本重跑。

目前没有系统运行输出；不得在审核表内预先写准确率、召回提升、耗时/费用优势或公司实际收益。
